# Архітектура MilLog

## Структура організації

Система працює з ієрархією підрозділів:

```
Бригада
  └── Полк
        └── Батальйон
              └── Рота
```

Склад з ресурсами знаходиться на рівні полку. За нього відповідає комірник.

---

## Ролі користувачів

| Роль      | Опис                          | Можливості                                           | 
|-----------|-------------------------------|------------------------------------------------------|
| ADMIN     | Адміністратор                 | Керування користувачами, налаштування, повний доступ |
| APPROVER  | Командир полку або батальйону | Затвердження або відхилення заявок                   |
| COMMANDER |   Командир                    | Створення заявок на ресурси для свого підрозділу     |
| WAREHOUSE |   Комірник                    | Облік ресурсів, категорії, прийом і видача           |
| VOLUNTEER |   Волонтер                    | Перегляд і виконання заявок для волонтерів           |

---

## Типи заявок

### Заявки на постачання (внутрішні)

Потік:

1. Користувач (COMMANDER) створює заявку на ресурс
2. Командир (APPROVER) затверджує або відхиляє
3. Після затвердження комірник видає ресурс зі складу
4. Залишок на складі оновлюється автоматично

### Заявки для волонтерів

Окремий тип заявок для зовнішніх допоміжних організацій:

- Військова частина створює потребу (одяг, медикаменти, обладнання)
- Волонтери бачать список таких заявок
- Волонтери можуть брати заявки в роботу і позначати їх виконаними

---

## Модель даних

**Підрозділи (units)** — ієрархія: бригада, полк, батальйон, рота. Кожен підрозділ має батьківський підрозділ, крім бригади.

**Користувачі (users)** — прив’язані до підрозділу через `unit_id`. Роль визначає права доступу.

**Ресурси (resources)** — прив’язані до складу (полку). Мають категорію, кількість, мінімальний залишок.

**Заявки на постачання (supply_requests)** — внутрішні заявки від користувачів на отримання ресурсів. Життєвий цикл: очікує, затверджено, відхилено.

**Заявки для волонтерів (volunteer_requests)** — окремі заявки, які створює військова частина. Волонтери їх переглядають і виконують.

## Компоненти системи

**Backend** — Go, Gin, PostgreSQL. REST API. JWT для авторизації.

**Frontend** — React, TypeScript. Сайдбар, dashboard, таблиці, форми.

**База даних** — PostgreSQL. Міграції при старті.
