# Опис архітектури програмного забезпечення

Архітектура програмного забезпечення визначає будову системи, її ключові компоненти та механізми взаємодії між ними. Для реалізації вебзастосунку обрано багатошарову клієнт-серверну архітектуру з чітким розділенням зон відповідальності на основі принципів REST API.

В основі системи лежить трирівнева архітектура. Клієнтська частина реалізована як односторінковий додаток на React з TypeScript. Серверна частина побудована на мові Go з фреймворком Gin. Рівень даних представлений реляційною базою PostgreSQL з підтримкою мультитенантності для одночасного обслуговування необмеженої кількості організацій.

Рівень представлення забезпечує інтерфейс користувача через компонентну архітектуру React. SPA-додаток реалізує маршрутизацію, управління станом через Context API та взаємодію з backend через Axios з автоматичним додаванням JWT-токенів до запитів.

Рівень бізнес-логіки організований за шаровим принципом: обробники (handlers) приймають HTTP-запити та валідують вхідні дані, сервіси (services) реалізують бізнес-правила та оркестрацію операцій, репозиторії (repositories) інкапсулюють логіку доступу до даних. Middleware забезпечує автентифікацію через JWT, перевірку прав доступу на основі ролей (RBAC), контроль тарифних обмежень та ізоляцію даних організацій.

Рівень даних використовує PostgreSQL з Row Level Security (RLS) для автоматичної ізоляції даних різних організацій. Кожна таблиця містить поле tenant_id, а RLS-політики на рівні СУБД блокують доступ до записів інших організацій. Connection pool налаштовує змінну app.tenant_id перед кожним запитом, забезпечуючи прозору фільтрацію на рівні бази даних.

Центральним елементом інфраструктури виступає Nginx як reverse proxy. Він обробляє HTTPS-з'єднання, маршрутизує запити до фронтенду (статичні файли) та бекенду (/api/*), забезпечує SSL/TLS-термінацію та перенаправлення HTTP на HTTPS. Контейнеризація через Docker Compose дозволяє розгортати всі компоненти системи ізольовано.

Мультитенантна архітектура реалізує SaaS-модель з повною ізоляцією даних. Кожна організація (tenant) має власний набір користувачів, ресурсів та підрозділів. Система підписок з тарифами (BASIC, PRO, ENTERPRISE) обмежує доступ до преміум-функцій через middleware. Автентифікація користувачів відбувається через email та пароль з видачею JWT-токена, що містить user_id, роль, tenant_id та термін дії. Узагальнена архітектура застосунку зображена на рис. 3.1.
