## 2. Проблематика (Вступ)

На основі аналізу коду виявлено, що система вирішує комплекс взаємопов'язаних проблем у сфері організаційної логістики:

### Головні проблеми, які вирішує система

1. **Відсутність єдиного цифрового середовища для управління ресурсами організації.**
   Традиційний облік матеріальних цінностей ведеться у розрізнених таблицях або паперових журналах, що унеможливлює оперативний контроль залишків на складах, відстеження переміщення майна та своєчасне поповнення запасів.

2. **Складність контролю транспортного парку та логістичних ланцюжків у реальному часі.**
   Відсутність централізованої системи відстеження транспортних засобів, маршрутів доставки та технічного стану флоту призводить до неефективного використання ресурсів, перевитрат пального та затримок у виконанні логістичних операцій.

3. **Відсутність автоматизованого контролю виконання заявок на забезпечення (SLA).**
   Заявки на постачання ресурсів часто залишаються без розгляду понад допустимий термін через відсутність механізмів ескалації та автоматичного оповіщення відповідальних осіб.

4. **Неможливість масштабування рішення для роботи кількох організацій (відсутність мультиорендності).**
   Існуючі рішення, як правило, є монолітними і не підтримують ізольовану роботу кількох незалежних організацій (tenant) в одній системі з різними тарифними планами та правами доступу.

## 3. Опис архітектури та технологій (Основна частина)

### 3.1 Стек технологій

| Шар | Технологія |
|---|---|
| **Бекенд** | Go 1.24, фреймворк Gin |
| **База даних** | PostgreSQL (драйвер pgx/v5, connection pool) |
| **Аутентифікація** | JWT (access token) + Refresh Token (ротація) |
| **Фронтенд** | React 18 + TypeScript, збірник Vite |
| **Інтерактивні карти** | React-Leaflet + Leaflet.js |
| **Графіки та аналітика** | Recharts |
| **Генерація документів** | gofpdf (PDF), excelize (Excel/XLSX) |
| **QR-коди** | go-qrcode (бекенд), html5-qrcode (сканування на фронті) |
| **Розгортання** | Docker + Docker Compose, Nginx/Caddy reverse proxy |
| **Email-розсилки** | SMTP через gomail |

### 3.2 Модульна структура системи

#### Модуль 1: Мультиорендна платформа (Multi-tenancy)
- Кожна організація — окремий **tenant** з ізольованими даними.
- Тарифні плани: **BASIC → PRO → ENTERPRISE** з автоматичним downgrade при закінченні підписки.
- Платформний адміністратор (`SYSTEM_ADMIN`) управляє всіма tenants через окремий API (`/api/platform`).

#### Модуль 2: Рольова модель доступу (RBAC)
Система реалізує **ієрархічну** рольову модель із 14 ролями, що відповідають реальній організаційній структурі:

```
SYSTEM_ADMIN > TENANT_ADMIN
  └── REGION_DIRECTOR / REGION_LOGISTICIAN / REGION_STOREKEEPER
        └── BRANCH_MANAGER / BRANCH_LOGISTICIAN / BRANCH_STOREKEEPER
              └── DEPT_MANAGER / DEPT_SUPERVISOR
                    └── TEAM_LEAD
                          └── EMPLOYEE
CONTRACTOR  (зовнішній підрядник)
```

Middleware `RequireAnyRole` та `RequireSubscriptionTier` динамічно перевіряють права на кожен endpoint.

#### Модуль 3: Управління складами та інвентарем
- CRUD-операції над категоріями, ресурсами, складами.
- **Переміщення майна (Shipments):** повний lifecycle — створення → відправлення → отримання з PDF-накладною.
- **QR-кодування** кожної одиниці майна для швидкого пошуку через кіоск-термінал (`/kiosk`).
- **Imпорт з Excel (PRO):** масовий імпорт ресурсів за шаблоном XLSX.
- Видача майна конкретним співробітникам та перегляд особистого спорядження (`/my-equipment`).

#### Модуль 4: Система заявок на постачання з SLA-моніторингом
- Lifecycle заявки: `PENDING → APPROVED / REJECTED / ESCALATED / CANCELLED`.
- **SLA Monitor** — фоновий горутин (`ticker`), що щохвилини перевіряє прострочені заявки та автоматично переводить їх у статус `ESCALATED` із надсиланням email-оповіщення керівнику.
- **Smart Dispatch (PRO)** — алгоритм автоматичного підбору складів для виконання заявки з попереднім переглядом розподілу ресурсів.
- **Smart Replenishment (PRO)** — автоматичне формування заявок на поповнення на основі порогових залишків.

#### Модуль 5: GPS-відстеження та геозони (PRO)
- Водій пінгує координати через мобільний браузер (endpoint `POST /api/gps/driver/ping`).
- Бекенд автоматично визначає транспортний засіб водія через активний рейс (`IN_TRANSIT`).
- **Fleet Map** — інтерактивна карта (Leaflet) з динамічними SVG-іконками вантажівок: колір залежить від швидкості, стрілка — від напрямку руху, є анімовані пульсуючі кільця.
- **Геозони** — визначення полігональних зон, автоматичне оповіщення при порушенні меж.
- **Trajectory** — відображення маршруту транспортного засобу за вибраний проміжок часу.

#### Модуль 6: Управління транспортним парком
- Облік транспортних засобів, їх статусів (`AVAILABLE / IN_TRANSIT / MAINTENANCE / DECOMMISSIONED`).
- Журнал заправок із розрахунком витрат пального.
- **Детекція аномалій витрат пального (PRO)** — статистичний аналіз записів заправок для виявлення підозрілих відхилень.
- Журнал технічного обслуговування з можливістю прикріплення файлів.

#### Модуль 7: Аналітика та прогнозування (PRO)
- **Dashboard:** метрики SLA-виконання, TCO (Total Cost of Ownership), індикатори ризиків.
- **KPI Dashboard:** розширені показники ефективності підрозділів.
- **Demand Forecast:** прогнозування потреби у ресурсах на основі статистики минулих заявок.
- **Predictive Maintenance:** предиктивний розклад технічного обслуговування на основі пробігу та часу.
- **Експорт:** звіти у форматах Excel (XLSX) та PDF.

#### Модуль 8: Робота з підрядниками (Contractor Workflow)
- Військові створюють заявки на допомогу, підрядники `CONTRACTOR` беруть їх в роботу та підтверджують доставку.
- Lifecycle: `OPEN → IN_PROGRESS → DELIVERED → ACCEPTED / REJECTED`.

#### Модуль 9: Сповіщення та аудит
- In-app сповіщення з лічильником непрочитаних.
- Журнал аудиту всіх критичних дій (хто, коли, що змінив) — зберігається в БД.

### 3.3 Алгоритми та підходи, що є досягненнями

| # | Алгоритм / підхід | Де реалізовано |
|---|---|---|
| 1 | **SLA Escalation Algorithm** — фоновий моніторинг із автоматичною зміною статусу та ескалацією сповіщень | `services/sla_monitor.go` |
| 2 | **Smart Dispatch Algorithm** — жадібний алгоритм розподілу ресурсів між складами для виконання заявки | `services/request_service.go` |
| 3 | **Geofence Breach Detection** — перевірка входу/виходу транспортного засобу із визначеної зони за GPS-координатами | `services/gps_tracking_service.go` |
| 4 | **Fuel Anomaly Detection** — статистичне виявлення аномалій у витратах пального (Z-score або IQR підхід) | `services/analytics_service.go` |
| 5 | **Demand Forecasting** — прогнозування попиту на ресурси на основі ковзного середнього / трендового аналізу | `services/analytics_service.go` |
| 6 | **Recursive Unit Hierarchy** — рекурсивний SQL-запит (`WITH RECURSIVE`) для обходу ієрархії підрозділів і визначення тарифу | `middleware/subscription.go` |
| 7 | **JWT + Refresh Token Rotation** — безпечна схема аутентифікації із ротацією refresh-токенів | `services/auth_service.go`, `tokens/` |
| 8 | **Real-time SVG Vehicle Icons** — динамічна генерація SVG-іконок транспортних засобів на основі швидкості, курсу та номерного знаку | `pages/GPSTracking.tsx` |

### 3.4 Безпека
- Rate Limiting на auth-endpoints (10 спроб / 5 хвилин з однієї IP).
- Security Headers middleware (CSP, X-Frame-Options тощо).
- CORS-захист із whitelist дозволених origin.
- Захист від path traversal при скачуванні файлів ТО.
- Логування спроб несанкціонованого доступу до PRO-функцій.

## 4. Висновки

**Головний результат впровадження системи** — створення єдиної мультиорендної SaaS-платформи для управління логістикою організацій, яка забезпечує:

1. **Пришвидшення обробки заявок** завдяки автоматизованій ескалації SLA та алгоритму Smart Dispatch — час від подачі заявки до її виконання скорочується за рахунок усунення людського фактору в маршрутизації.

2. **Підвищення ефективності використання транспортного парку** завдяки GPS-моніторингу в реальному часі, предиктивному обслуговуванню та детекції аномалій витрат пального.

3. **Оптимізацію управління матеріальними запасами** через алгоритм Smart Replenishment, що автоматично формує заявки при досягненні порогового рівня залишків, та прогнозування попиту.

4. **Масштабованість та ізольованість** завдяки мультиорендній архітектурі — платформа підтримує необмежену кількість незалежних організацій з різними тарифними планами без зміни кодової бази.

5. **Повну прозорість операцій** через журнал аудиту та аналітичні дашборди з KPI.
