# Діаграми послідовності основних функціоналів системи

## 1. Реєстрація нового користувача (Tenant Signup)

### Опис процесу
Публічний endpoint для self-service реєстрації нової організації. Створює нового tenant (організацію) та першого користувача з роллю `TENANT_ADMIN`.

### Діаграма послідовності

```
┌─────────────┐        ┌──────────────┐        ┌──────────────┐        ┌────────────────┐
│   Frontend  │        │   Backend    │        │  PostgreSQL  │        │   Email Svc    │
│   (UI)      │        │   (Gin/Go)   │        │   (Database) │        │   (SMTP)       │
└──────┬──────┘        └──────┬───────┘        └──────┬───────┘        └────────┬───────┘
       │                      │                       │                         │
       │  1. POST /auth/tenants/signup                │                         │
       │  (organizationName, slug, ownerEmail,        │                         │
       │   ownerFullName, ownerPassword)              │                         │
       ├─────────────────────────────────────────────>│                         │
       │                      │                       │                         │
       │                      │ 2. Валідація вхідних даних                       │
       │                      │    • Перевірка емейлу                            │
       │                      │    • Перевірка складності пароля                 │
       │                      │    │                       │                     │
       │                      │    • Хеш пароля bcrypt     │                     │
       │                      │    • Генерація UUID tenant_id                    │
       │                      │                       │                         │
       │                      │ 3. BEGIN TRANSACTION  │                         │
       │                      ├──────────────────────>│                         │
       │                      │                       │                         │
       │                      │ 4. INSERT INTO tenants (id, name, slug,         │
       │                      │    subscription_tier='BASIC', is_active=true)   │
       │                      ├──────────────────────>│                         │
       │                      │    ✓ tenant_id        │                         │
       │                      │<──────────────────────┤                         │
       │                      │                       │                         │
       │                      │ 5. INSERT INTO users (id, email, password_hash,  │
       │                      │    role='TENANT_ADMIN', tenant_id, is_blocked=0)│
       │                      ├──────────────────────>│                         │
       │                      │    ✓ user_id          │                         │
       │                      │<──────────────────────┤                         │
       │                      │                       │                         │
       │                      │ 6. INSERT INTO audit_logs                        │
       │                      │    (action='CREATE', entity='TENANT', ...)       │
       │                      ├──────────────────────>│                         │
       │                      │<──────────────────────┤                         │
       │                      │                       │                         │
       │                      │ 7. COMMIT TRANSACTION │                         │
       │                      ├──────────────────────>│                         │
       │                      │    ✓ Success          │                         │
       │                      │<──────────────────────┤                         │
       │                      │                       │                         │
       │                      │ 8. [async] Надіслати email                       │
       │                      │                                 ┌──────────────>│
       │                      │                                 │ Привіт! Ваш  │
       │                      │                                 │ організація  │
       │                      │                                 │ готова до    │
       │                      │                                 │ використання │
       │                      │                                 │<──────────────┤
       │                      │                                 │               │
       │ 9. HTTP 201 Created  │                       │                         │
       │ {tenant_id, owner_id,│                       │                         │
       │  message}            │                       │                         │
       │<─────────────────────┤                       │                         │
       │                      │                       │                         │
```

### Послідовність дій:

1. **Валідація вхідних даних**
   - Перевірка email-формату
   - Перевірка пароля на складність (мін. 8 символів, велика літера, цифра, спецсимвол)
   - Перевірка унікальності slug та email

2. **Транзакція в БД**
   - INSERT в таблицю `tenants` з тарифом `BASIC` і статусом `is_active=true`
   - INSERT в таблицю `users` з роллю `TENANT_ADMIN` і хешованим паролем
   - INSERT в таблицю `audit_logs` для логування операції

3. **Асинхронне відправлення email**
   - Email надсилається в фоновому горутині (не блокує основний потік)

4. **Відповідь клієнту**
   - HTTP 201 Created з `tenant_id` та `owner_id`

## 2. Реєстрація нового користувача (RegisterUser)

### Опис процесу
Адміністратор (TENANT_ADMIN, ADMIN, REGION_DIRECTOR тощо) реєструє нового користувача в межах своєї організації. Заявка йде на затвердження, поки користувач не активований.

### Діаграма послідовності

```
┌─────────────┐        ┌──────────────┐        ┌──────────────┐        ┌────────────────┐
│   Frontend  │        │   Backend    │        │  PostgreSQL  │        │   Email Svc    │
│   (UI)      │        │   (Gin/Go)   │        │   (Database) │        │   (SMTP)       │
└──────┬──────┘        └──────┬───────┘        └──────┬───────┘        └────────┬───────┘
       │                      │                       │                         │
       │  1. POST /admin/users                        │                         │
       │  {fullName, email, phone, role, unit_id}    │                         │
       │  Headers: Authorization: Bearer <JWT>        │                         │
       ├─────────────────────────────────────────────>│                         │
       │                      │                       │                         │
       │                      │ 2. AuthMiddleware: Перевірка JWT                 │
       │                      │    • Розпаковка токена                           │
       │                      │    • Перевірка експірейшену                      │
       │                      │    • Витяг user_id, role, tenant_id              │
       │                      │    │                       │                     │
       │                      │ 3. RequireAnyRole middleware                      │
       │                      │    • Перевірка creatorRole у дозволених ролях    │
       │                      │    • Якщо creatorRole не в [ADMIN, TENANT_ADMIN, │
       │                      │      REGION_DIRECTOR, ...] → HTTP 403            │
       │                      │    │                       │                     │
       │                      │ 4. Валідація                                       │
       │                      │    • CanCreate(creatorRole, targetRole)?           │
       │                      │    • Якщо false → error "не має прав"             │
       │                      │    │                       │                     │
       │                      │ 5. BEGIN TRANSACTION      │                     │
       │                      ├──────────────────────────>│                     │
       │                      │                           │                     │
       │                      │ 6. Генерація тимчасового пароля                 │
       │                      │    (або запрошення токена)                       │
       │                      │    • Генерація UUID для invite_token             │
       │                      │    │                       │                     │
       │                      │ 7. INSERT INTO users (role='PENDING',             │
       │                      │    is_blocked=true, created_by=creatorID)       │
       │                      ├──────────────────────────>│                     │
       │                      │    ✓ user_id               │                     │
       │                      │<──────────────────────────┤                     │
       │                      │                           │                     │
       │                      │ 8. INSERT INTO invite_tokens                     │
       │                      │    (user_id, token, expires_at)                 │
       │                      ├──────────────────────────>│                     │
       │                      │<──────────────────────────┤                     │
       │                      │                           │                     │
       │                      │ 9. INSERT INTO audit_logs                        │
       │                      │    (action='CREATE', entity='USER', user_id=...) │
       │                      ├──────────────────────────>│                     │
       │                      │<──────────────────────────┤                     │
       │                      │                           │                     │
       │                      │ 10. COMMIT                │                     │
       │                      ├──────────────────────────>│                     │
       │                      │    ✓ Success              │                     │
       │                      │<──────────────────────────┤                     │
       │                      │                           │                     │
       │                      │ 11. [async] Надіслати invite-email               │
       │                      │     з посиланням: /setup-password?token=...      │
       │                      │                                ┌────────────────>│
       │                      │                                │ Ви запрошені   │
       │                      │                                │ до системи:    │
       │                      │                                │ [посилання]    │
       │                      │                                │<────────────────┤
       │                      │                                │                 │
       │ 12. HTTP 201 Created │                           │                     │
       │ {id, message}        │                           │                     │
       │<─────────────────────┤                           │                     │
       │                      │                           │                     │
```

### Послідовність дій:

1. **Аутентифікація та авторизація**
   - Перевірка JWT-токена (вже залогінений користувач)
   - Перевірка ролі (тільки адміністратори можуть реєструвати)

2. **Валідація прав**
   - Матриця прав: `CanCreate(creatorRole, targetRole)`
   - ADMIN може створити будь-кого
   - REGION_DIRECTOR може створити тільки підлеглих ролей

3. **Транзакція в БД**
   - INSERT в `users` з роллю `PENDING` та флагом `is_blocked=true`
   - INSERT в `invite_tokens` з посиланням на активацію
   - INSERT в `audit_logs`

4. **Асинхронне відправлення email**
   - Email з посиланням на форму установки пароля

## 3. Створення заявки на постачання (Create Supply Request)

### Опис процесу
Користувач створює нову заявку на постачання ресурсу з одного складу на інший. Заявка проходить затвердження у керівника, потім виконується.

### Діаграма послідовності

```
┌─────────────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│     Frontend        │        │   Backend    │        │  PostgreSQL  │        │  Audit/      │
│     (UI/Form)       │        │   (Gin/Go)   │        │   (Database) │        │ Notification │
└──────┬──────────────┘        └──────┬───────┘        └──────┬───────┘        └──────┬───────┘
       │                              │                       │                       │
       │  1. POST /requests            │                       │                       │
       │  {resourceID, quantity,       │                       │                       │
       │   resourceName, category_id,  │                       │                       │
       │   targetWarehouseID}          │                       │                       │
       ├─────────────────────────────────────────────────────>│                       │
       │                              │                       │                       │
       │                              │ 2. AuthMiddleware     │                       │
       │                              │    Витяг: user_id,    │                       │
       │                              │    role, unit_id      │                       │
       │                              │    │                 │                       │
       │                              │ 3. Валідація даних    │                       │
       │                              │    • resourceID exist? │                       │
       │                              │    • quantity > 0?    │                       │
       │                              │    • warehouse exist?  │                       │
       │                              │    │                 │                       │
       │                              │ 4. Витяг ролі автора  │                       │
       │                              ├─────────────────────>│                       │
       │                              │ SELECT * FROM users   │                       │
       │                              │ WHERE id = user_id    │                       │
       │                              │    ✓ creator_role     │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 5. Логіка статусу:    │                       │
       │                              │    IF role IN [       │                       │
       │                              │      TENANT_ADMIN,    │                       │
       │                              │      SYSTEM_ADMIN,    │                       │
       │                              │      ADMIN            │                       │
       │                              │    ]                  │                       │
       │                              │    status = APPROVED  │                       │
       │                              │    ELSE               │                       │
       │                              │    status = PENDING   │                       │
       │                              │                       │                       │
       │                              │ 6. BEGIN TRANSACTION  │                       │
       │                              ├─────────────────────>│                       │
       │                              │                       │                       │
       │                              │ 7. INSERT INTO        │                       │
       │                              │    supply_requests    │                       │
       │                              │    (id, created_by,   │                       │
       │                              │     resource_id,      │                       │
       │                              │     quantity,         │                       │
       │                              │     status,           │                       │
       │                              │     created_at)       │                       │
       │                              ├─────────────────────>│                       │
       │                              │    ✓ request_id       │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 8. IF status=APPROVED │                       │
       │                              │    UPDATE supply_     │                       │
       │                              │    requests:          │                       │
       │                              │    approved_by=user_id│                       │
       │                              │    approved_at=NOW()  │                       │
       │                              ├─────────────────────>│                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 9. COMMIT            │                       │
       │                              ├─────────────────────>│                       │
       │                              │    ✓ Success          │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 10. [async] LogAction │                       │
       │                              │────────────────────────────────────────────>│
       │                              │                       │    Створено нову    │
       │                              │                       │    заявку           │
       │                              │                       │<────────────────────┤
       │                              │                       │                     │
       │ 11. HTTP 201 Created         │                       │                     │
       │ {                             │                       │                     │
       │   id, created_by,             │                       │                     │
       │   resource_name,              │                       │                     │
       │   quantity, status,           │                       │                     │
       │   created_at                  │                       │                     │
       │ }                             │                       │                     │
       │<──────────────────────────────┤                       │                     │
       │                              │                       │                     │
```

### Послідовність дій:

1. **Аутентифікація та валідація**
   - Перевірка JWT-токена
   - Валідація вхідних даних (ресурс, склад існують)

2. **Визначення статусу заявки**
   - ADMIN/TENANT_ADMIN → статус = `APPROVED` (самопогодження)
   - Звичайний користувач → статус = `PENDING` (очікує затвердження)

3. **Транзакція в БД**
   - INSERT в `supply_requests`
   - Якщо статус = APPROVED, одразу проставляємо `approved_by` та `approved_at`

4. **Асинхронне логування**
   - В фоновому горутині записуємо в `audit_logs`

## 4. Затвердження заявки (Approve Supply Request)

### Опис процесу
Керівник розглядає заявку і затверджує або відхиляє її. При затвердженні заявка переходить у статус `APPROVED` та стає готовою до виконання.

### Діаграма послідовності

```
┌─────────────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│     Frontend        │        │   Backend    │        │  PostgreSQL  │        │   Audit/    │
│     (UI/Approval)   │        │   (Gin/Go)   │        │   (Database) │        │  Notif Svc  │
└──────┬──────────────┘        └──────┬───────┘        └──────┬───────┘        └──────┬───────┘
       │                              │                       │                       │
       │  1. POST /requests/:id/approve                       │                       │
       │  {approved: true, comment: "..."}                    │                       │
       │  Headers: Authorization: Bearer <JWT>                │                       │
       ├─────────────────────────────────────────────────────>│                       │
       │                              │                       │                       │
       │                              │ 2. AuthMiddleware     │                       │
       │                              │    Витяг: user_id,    │                       │
       │                              │    approver_role      │                       │
       │                              │    │                 │                       │
       │                              │ 3. BEGIN TRANSACTION  │                       │
       │                              ├─────────────────────>│                       │
       │                              │                       │                       │
       │                              │ 4. SELECT * FROM      │                       │
       │                              │    supply_requests    │                       │
       │                              │    WHERE id=...       │                       │
       │                              ├─────────────────────>│                       │
       │                              │    ✓ request data     │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 5. Валідація статусу  │                       │
       │                              │    IF status !=       │                       │
       │                              │       PENDING         │                       │
       │                              │    THEN error:        │                       │
       │                              │    "вже оброблена"    │                       │
       │                              │    │                 │                       │
       │                              │ 6. Валідація конф.    │                       │
       │                              │    IF approver_id ==   │                       │
       │                              │       creator_id      │                       │
       │                              │    THEN error:        │                       │
       │                              │    "конфлікт інтересів│                       │
       │                              │    │                 │                       │
       │                              │ 7. Витяг автора       │                       │
       │                              ├─────────────────────>│                       │
       │                              │ SELECT * FROM users   │                       │
       │                              │ WHERE id=creator_id   │                       │
       │                              │    ✓ creator_role     │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 8. Перевірка матриці  │                       │
       │                              │    прав затвердження  │                       │
       │                              │    CanApprove(        │                       │
       │                              │      creator_role,    │                       │
       │                              │      approver_role    │                       │
       │                              │    )?                 │                       │
       │                              │    IF false → error   │                       │
       │                              │    "недостатньо прав" │                       │
       │                              │    │                 │                       │
       │                              │ 9. UPDATE            │                       │
       │                              │    supply_requests    │                       │
       │                              │    SET:               │                       │
       │                              │    status=APPROVED,   │                       │
       │                              │    approved_by=       │                       │
       │                              │      approver_id,     │                       │
       │                              │    approved_at=NOW()  │                       │
       │                              ├─────────────────────>│                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 10. COMMIT           │                       │
       │                              ├─────────────────────>│                       │
       │                              │    ✓ Success          │                       │
       │                              │<─────────────────────┤                       │
       │                              │                       │                       │
       │                              │ 11. [async] LogAction │                       │
       │                              │────────────────────────────────────────────>│
       │                              │                       │    Погоджено    │
       │                              │                       │    заявку      │
       │                              │                       │<────────────────┤
       │                              │                       │                     │
       │                              │ 12. [async] Notify    │                     │
       │                              │     creator           │                     │
       │                              │                       │                     │
       │ 13. HTTP 200 OK              │                       │                     │
       │ {message: "Заявку            │                       │                     │
       │ успішно оброблено"}          │                       │                     │
       │<──────────────────────────────┤                       │                     │
       │                              │                       │                     │
```

### Послідовність дій:

1. **Аутентифікація**
   - Перевірка JWT-токена затверджувача

2. **Валідація**
   - Заявка повинна мати статус `PENDING`
   - Затверджувач не может затвердити власну заявку (конфлікт інтересів)

3. **Перевірка прав**
   - Матриця: кожна роль автора має певний список ролей, що можуть затвердити
   - Приклад: заявка від TEAM_LEAD може бути затверджена DEPT_MANAGER чи вище

4. **Транзакція в БД**
   - UPDATE `supply_requests` статус → `APPROVED`
   - Проставити `approved_by` та `approved_at`

5. **Асинхронні операції**
   - Логування в `audit_logs`
   - Email-нотифікація автору заявки

## 5. Виконання заявки / Отримання вантажу (Receive Shipment)

### Опис процесу
Після доставки вантажу комірник (storekeeper) приймає його через мобільний/браузер, сканує QR-код вантажу, перевіряє кількість та оновлює залишки на складі.

### Діаграма послідовності

```
┌──────────────────────┐        ┌──────────────┐        ┌──────────────┐        ┌──────────────┐
│     Frontend         │        │   Backend    │        │  PostgreSQL  │        │   Notif/    │
│ (Mobile/Kiosk)       │        │   (Gin/Go)   │        │   (Database) │        │  Audit      │
└──────┬───────────────┘        └──────┬───────┘        └──────┬───────┘        └──────┬───────┘
       │                              │                       │                       │
       │  1. POST /inventory/shipments/:id/receive             │                       │
       │  {items: [{resource_id, scanned_qty}, ...]}          │                       │
       │  Headers: Authorization: Bearer <JWT>                │                       │
```

### Послідовність дій:

1. **Аутентифікація та авторизація**
   - Перевірка JWT-токена комірника
   - Перевірка ролі: тільки Storekeeper/Admin можуть приймати

2. **Валідація рейсу**
   - Рейс повинен мати статус `IN_TRANSIT`

3. **Оновлення залишків**
   - ДЛЯ КОЖНОГО ITEM у вантажі:
     - Прочитати поточну кількість в БД
     - Перевірити совпадение зі складеною кількістю
     - UPDATE `resources` з новою кількістю
     - INSERT в `shipment_items` з деталями отримання

4. **Логування**
   - INSERT в `audit_logs` з деталями отримання (кількість, хто, коли)

5. **Асинхронні операції**
   - Email-нотифікація всім причетним

## Ключові паттерни в системі

### 1. **Аутентифікація (JWT)**
Всі endpoints (крім `/auth/login`, `/auth/register`, `/auth/tenants/signup`) обов'язково проходять через `AuthMiddleware`:
- Витяг JWT-токена з заголовку `Authorization: Bearer <token>`
- Перевірка підпису та експірейшену
- Витяг claims: user_id, role, tenant_id, unit_id

### 2. **Авторизація (RBAC)**
- Кожен endpoint захищений `RequireAnyRole([]Role{...})`
- Матриця прав визначена в моделях (`models/auth.go`)

### 3. **Тарифні обмеження**
- Преміум-функції (GPS, Analytics, Excel Import) захищені `RequireSubscriptionTier("PRO", dbPool)`

### 4. **Мультиорендність**
- Кожен запит містить контекст `tenant_id` (з JWT)
- Row Level Security (RLS) на рівні БД автоматично фільтрує дані

### 5. **Асинхронність**
- Довгі операції (email, логування) виконуються в окремих горутинах
- Не блокують основний потік обробки запиту

### 6. **Транзакції**
- Багатокрокові операції загорнуті в `BEGIN...COMMIT` для атомарності
- При помилці автоматичний `ROLLBACK`
