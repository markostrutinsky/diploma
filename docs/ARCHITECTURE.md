# Архітектура Omnilog

## Структура організації

Ієрархія підрозділів:

```
Бригада
  └── Батальйон
        └── Рота
              └── Взвод
```

### Склади (зони)

| Рівень   | Зона  | Опис                                                                 |
|----------|-------|----------------------------------------------------------------------|
| Бригада  | Зелена | Головний склад. Ресурси від Міноборони. Великі обсяги, далеко від фронту |
| Батальйон| Жовта | Оперативний резерв. Менші обсяги ніж бригадні                        |
| Рота     | Червона| Кінцева точка видачі. Відповідальний — старшина роти                 |

## Ролі користувачів

### Командири (за рівнем)
| Роль           | Опис              |
|----------------|-------------------|
| REGION_DIRECTOR   | Командир бригади  |
| BRANCH_MANAGER | Командир батальйону |
| DEPT_MANAGER   | Командир роти     |
| TEAM_LEAD   | Командир взводу   |

### Логісти та комірники (за рівнем)
| Роль                 | Опис                    |
|----------------------|-------------------------|
| REGION_LOGISTICIAN       | Логіст бригади — планування, заявки, звіти |
| REGION_STOREKEEPER  | Комірник бригади — фізичний прийом/видача зі складу |
| BRANCH_LOGISTICIAN     | Логіст батальйону — збір потреб рот, розподіл |
| BRANCH_STOREKEEPER| Комірник батальйону — прийом з бригади, видача старшинам |
| DEPT_SUPERVISOR     | Старшина роти — матеріально-відповідальна особа, видача солдатам |

### Інші
| Роль     | Опис                                      |
|----------|-------------------------------------------|
| ADMIN    | Адміністратор системи                      |
| CONTRACTOR| Волонтер — самореєстрація, виконання заявок |

---

## Делегування прав

- **Адмін** — створює всіх користувачів, крім CONTRACTOR (волонтери реєструються самі).
- **Командир бригади** — створює комбата, ротних, взводних, логістів і комірників у своїй ієрархії.
- **Комбат** — створює ротних, взводних, логістів і комірників батальйону.
- **Підрозділи** — створюються за ієрархією: бригада (адмін) → батальйон → рота → взвод.

---

## Типи заявок

### Заявки на постачання (внутрішні)

1. Командир/старшина створює заявку на ресурс
2. Вищестоящий командир або логіст затверджує
3. Комірник видає зі складу
4. Залишок оновлюється автоматично

### Заявки для волонтерів

- Військова частина створює потребу
- Волонтери переглядають, беруть у роботу, позначають виконаними

---

## Реєстрація та авторизація

- **Access token** — короткоживучий JWT для API.
- **Refresh token** — зберігається в БД, дозволяє відкликати доступ.
- **Invite token** — одноразовий токен для встановлення паролю (лист на пошту).
- **Волонтер** — публічна реєстрація без запрошення.

---

## Модель даних

**Підрозділи (units)** — BRIGADE → BATTALION → COMPANY → PLATOON.

**Користувачі (users)** — прив’язка до підрозділу через `unit_id`.

**Ресурси (resources)** — прив’язка до складу через `unit_id` (бригада/батальйон/рота).

**Заявки на постачання (supply_requests)** — внутрішній потік.

**Заявки для волонтерів (CONTRACTOR_requests)** — для зовнішніх організацій.

---

## API

**Auth** — POST /auth/login, POST /auth/refresh, POST /auth/register (волонтер), POST /auth/setup-password.

**Units** — GET/POST /api/units. Створюють за ієрархією.

**Inventory** — ресурси з фільтром по unit_id (складу).

**Supply requests** — створюють командири/старшини, затверджують логісти/командири.

**CONTRACTOR requests** — створюють військові, виконують волонтери.
